# 汉兜评价算法：设计、概率模型与实现

本文是汉兜（Handle）评价模块的独立设计文档，也是实现维护指南。目标读者是已经了解汉兜基本玩法，但没有参与评价算法讨论的程序员。

本文描述当前 `EVAL_VERSION = 5` 的生产实现。文中的 V1、V2、V3 是算法迭代名称，不与持久化版本号一一对应。

读完本文后，应当能够回答：

- 汉兜中的“好猜测”是什么意思；
- 评价所用的随机变量、先验和信息熵分别是什么；
- 为什么评价空间中会存在不是真实成语的虚拟拼音组合；
- V3 粒子、末盘枚举、声调后验和实际信息量如何配合；
- 如何从连续信息分数得到六档评价；
- 计算失败、刷新、模式切换和 Worker 延迟时会发生什么；
- 修改算法时哪些行为是产品规则，哪些是数学或工程不变量。

## 1. 问题和评价语义

### 1.1 汉兜提供的反馈

玩家每次猜一个四字成语。每个字有五个可见属性：

1. 汉字；
2. 声母；
3. 韵母；
4. 不含声调的全拼，例如 `cheng`；
5. 声调。

这五项是玩法层的语义。游戏内部为了兼容拼音、双拼和注音输入，把一次反馈保存为六个字段：

| 玩法属性 | 标准拼音模式下的内部字段 | 是否进入普通概率评分 |
|---|---|---|
| 汉字 | `char` | 否，只参与第 11 节的收束规则 |
| 声母 | `_1` | 是，对应 `F_I` |
| 韵母 | `_2` | 是，对应 `F_F` |
| 第三个拼音显示部件 | `_3`，标准拼音模式通常为空 | 否，不是额外的概率维度 |
| 全拼 | `py` | 是，对应 `F_full` |
| 声调 | `tone` | 是，对应 `F_T` |

`_1/_2/_3` 是游戏反馈对象的显示部件，不应直接等同于评价器的规范声母、韵母 ID；双拼或注音模式下它们可以采用不同拆分。评价器从不含声调的规范全拼重新解析 `F_I/F_F/F_full`，而 `matchesAllFeedback()` 重放游戏反馈时比较全部六个内部字段，保证特殊评级与玩家实际看到的输入模式一致。

因此，当前**普通评分只建模四种读音属性，不建模汉字**。汉字反馈仍然存在，也仍按游戏规则显示，但只参与“满足全部既有反馈”和“猜中”的离散规则。第 5.4、11、17.2 节会说明这样做的边界和代价。

每个属性采用 Wordle 式反馈：

- 灰色（`none`）：没有剩余答案元素与该查询匹配；
- 红色（`misplaced`）：存在匹配元素，但位置错误；
- 绿色（`exact`）：元素和位置都正确。

重复元素必须先匹配所有绿色，再将剩余查询从左到右匹配到尚未占用的答案位置，多余重复项为灰色。评价器必须与游戏的 `testAnswer()` 使用同一规则，否则真实答案会在后验过滤中被错误删除。

零声母是这段表述的一个可见性例外：`安 an` 之类的音节没有可供玩家查询的声母块，所以声母维度会跳过该位置，而不是把“空声母”当作一个可获得红绿反馈的元素。第 4.3 节给出精确编码。

### 1.2 评价的是猜前决策，不是猜后运气

主评价回答的问题是：

> 在本次提交之前的公开反馈下，这个猜测平均能够把当前模型中的可能情况区分得多好？

因此，普通评级使用猜测的**期望信息增益**。它不因为本轮碰巧获得大量绿色而提高，也不因为本轮碰巧全灰而降低。

更准确地说，声韵全拼项 `E1` 和声调项 `E2` 分别是各自近似模型中的期望信息增益；最终用于排名的 `E=E1+wE2` 是产品定义的**加权决策分数**。当 `w≠1` 时，`E` 不再是某个联合随机变量的标准 Shannon 互信息。本文沿用“信息评分”这一简称，但不会把权重 `w` 解释成概率定理。

这个分数也不直接求解“从现在开始最少还需几猜”的全局动态规划。它衡量的是单步区分能力，再由信息饱和压缩和特殊评级补充收束行为。这是当前产品对“好猜测”的定义，不是声称单步熵在所有盘面都严格最小化期望猜数。

例如，`搭搭撒撒` 可能偶然就是谜底，但这不使它成为优秀的首猜。反过来，一个统计上很好的首猜也可能碰巧得到很少信息。早期曾考虑额外显示 `lucky/unlucky`，当前已经明确放弃。

最终猜中和“满足全部既有反馈”有单独的评级下限；这是产品层的收束规则，不改变普通信息熵的猜前语义。

### 1.3 评价空间不是“真实答案候选集”

当前评价器有一个必须先说明的设计选择：

> 它主要评价猜测对**当前拼音约束空间**的辨别能力，而不是玩家在 44010 条真实成语（当前成语库内的所有成语）中做贝叶斯最优决策的能力。

现行支持的合法猜测和谜底应当能在成语找到对应语料行。因而在正常、未损坏的会话中，真实答案对应的行应始终通过与其属性有关的历史过滤。本文所说“词库稀疏”通常指联合后验只剩一条或少数几条，不是指真实答案允许完全落在评价语料之外。

`ifPyRows` 为空、真实反馈在语料后验中零命中、或完整末盘约束矛盾，原则上都违反上述不变量。实现仍保留防御性分支，以免一次解析、恢复或状态异常立刻破坏整个会话；这些分支不应被理解为正常的“虚拟空间接管真实谜底”。

真实语料仍然非常重要：它提供声母、韵母、音节、声调和重复结构的先验，也提供 V3 的真实粒子。但语料中的“存在或不存在某个完整成语”不能成为中后盘唯一的逻辑依据。

原因是现实成语库非常稀疏。只剩一条满足全部反馈的真实成语，不代表人类已经仅凭公开拼音条件锁定了它。人类通常不会枚举 44010 个成语并利用“词典中没有另一条记录”来推理；他仍面对许多语音上合理、但没有被语料收录为成语的组合。

所以 V3 和末盘模型允许虚拟四音节组合参与评分。这些组合：

- 不被宣称为真实答案；
- 不是对真实成语分布的无偏估计；
- 只用于补全公开反馈所描述的拼音逻辑空间；
- 必须由语料支持的合法音节组成，并按真实频率和重复结构校准。

这是一个有意的评价语义，而不只是性能近似。

## 2. 现行算法一览

本节集中定义一轮评价。后续章节再展开粒子如何生成、后验如何更新，以及为什么算法演化成现在的形式。

### 2.1 猜前随机变量

设：

- `h`：本猜之前的全部公开反馈历史；
- `g`：准备评价的四字猜测；
- `X_PY`：当前模型中的四音节假设；
- `X_T`：当前模型中的四声调假设。

除非特别说明，后文所有概率、熵和后验都默认以提交前历史 `h` 为条件，猜测 `g` 视为固定决策。为避免公式过长，本文省略条件记号 `\mid h`。本轮真实反馈尚未进入这些分布。

`X_PY` 的概率分布依盘面阶段而不同：

- 中前盘：4096 个 V3 等质量粒子形成的经验分布；
- 末盘：完整约束搜索得到的合法四音节组合及其显式归一化权重。

`X_T` 暂时独立建模。期望声调熵使用当前声调后验中至多 4096 个确定性样本；实际声调信息则遍历完整声调后验。

对于一个固定的假设 `x`，反馈完全由 `g` 和 `x` 决定：

\[
F_{PY}(g,x)=\bigl(F_I(g,x),F_F(g,x),F_{full}(g,x)\bigr)
\]

其中：

- `F_I` 输出四个声母的三态反馈码；
- `F_F` 输出四个韵母的三态反馈码；
- `F_full` 输出四个完整音节的三态反馈码。

声调反馈记为 `F_T(g,X_T)`。

### 2.2 为什么反馈熵等于期望信息增益

全文所有对数都以 2 为底，单位是 bit。离散随机变量 `Y` 的 Shannon 熵为：

\[
H(Y)=-\sum_y P(Y=y)\log_2P(Y=y)
\]

由于反馈是猜测和假想答案的确定性函数，已知 `X` 后不再有反馈不确定性：

\[
H(F(g,X)\mid X)=0
\]

因此，观察反馈后对假设 `X` 的期望信息增益为：

\[
I(X;F(g,X))=H(F(g,X))-H(F(g,X)\mid X)=H(F(g,X))
\]

所以算法只需按反馈码把带概率的假设分桶，再计算桶概率的熵。它算的不是“非空反馈桶有多少个”，而是这些桶的概率质量是否均匀：四个等概率桶有 2 bit，概率极不均衡的四个桶则远少于 2 bit。

声韵全拼部分必须联合计熵：

\[
E_1(g)=H\bigl(F_I(g,X_{PY}),F_F(g,X_{PY}),F_{full}(g,X_{PY})\bigr)
\]

声调部分为：

\[
E_2(g)=H\bigl(F_T(g,X_T)\bigr)
\]

本猜的普通连续分数是：

\[
E(g)=E_1(g)+w(J)E_2(g)
\]

这里 `w(J)` 是随累计信息增长的声调权重。玩家和所有基准词使用完全相同的猜前模型与权重。

`E1`、`E2` 各自是反馈熵；`E` 是它们的产品加权和。只有在 `w=1` 且接受拼音、声调独立建模时，`E1+E2` 才可视为该近似联合模型的总反馈熵。其余时候应把 `E` 称为“普通连续分数”，而不是严格互信息。

### 2.3 实际信息与累计约束量

提交后观察到真实反馈 `f`。如果当前模型给该事件的概率为 `p`，本猜实际信息是自信息：

\[
I=-\log_2p
\]

这一定义对末盘完整后验和完整声调后验是标准自信息。中前盘 `I1` 例外：第 7 节会用粒子命中数决定混合系数，把粒子频率与语料后验频率混成一个**针对已观察事件的工程概率估计**。因为不同反馈事件可能使用不同混合系数，这些事件估计不保证共同组成一个归一化概率分布。因此，中前盘 `I1` 更准确地说是“实际反馈惊讶度代理”，而不是固定先验下严格可加的 Shannon 信息量。

声韵全拼与声调分别得到 `I1`、`I2`，累计量为：

\[
J=\sum_{k<current}(I_{1,k}+I_{2,k})
\]

注意 `J` 是本猜**之前**的累计量；本猜得到的 `I1+I2` 只影响下一猜。

`J` 不乘声调权重。即：

\[
E=E_1+wE_2,\qquad I=I_1+I_2
\]

`J` 更准确的名称是**模型化的累计约束量**，而不是“关于真实谜底这一固定随机变量的标准 Shannon 信息量”。代码和诊断仍沿用 `I1/I2/information` 这些历史名称。原因是：

- `I1` 和 `I2` 来自分离后验；
- 中前盘含虚拟拼音假设；
- 后期会切换到另一套末盘先验；
- 汉字信息完全没有计入 `I1`、`I2`；
- 不同轮次的近似模型会随历史变化。
- 中前盘 `I1` 使用第 7 节的事件级平滑估计，不要求所有反馈事件的估计概率共同归一化。

因此这里不能直接套用单一固定概率模型的链式法则，`J` 可以超过 `log2(44010) ≈ 15.42 bit`。它的用途是缓慢控制声调紧迫性、信息饱和压缩和收束评级，不是估计真实词库还剩多少条，也不需要像普通排名分数 `E` 一样追求精确概率推断。

### 2.4 一轮评价的数据流

```text
上一猜反馈已处理
  ↓
从独立后验计算 N_I、N_F 和猜前累计 J
  ↓
N_I × N_F > 32：构造 V3 混合粒子
N_I × N_F ≤ 32：完整枚举末盘拼音后验
  ↓
抽样声调后验，计算固定 1000 个基准词的 E 并排序
  ↓
Worker 标记“下一猜已准备”
  ↓
玩家提交 g
  ↓
只计算玩家的 E1、E2、E，并在排序数组中二分得到基准样本百分位
  ↓
执行信息饱和压缩，得到普通评级
  ↓
用提交前历史检查“满足全部反馈”，并用本轮结果检查是否猜中
  ↓
普通评级与特殊评级下限取较高者
  ↓
由本轮真实反馈计算 I1、I2
  ↓
累计 J，过滤各后验，准备下一猜
```

评分与过滤的顺序不能交换。若先用本轮反馈过滤再评价，本猜刚获得的信息就会被错误地当成玩家提交前已经知道的信息。

### 2.5 核心变量表

| 符号/字段 | 含义 |
|---|---|
| `E1` | 猜前声母、韵母、全拼联合反馈熵 |
| `E2` | 猜前声调反馈熵 |
| `E` | `E1 + w(J)E2`，用于基准排名的产品加权连续分数；`w≠1` 时不是标准互信息 |
| `I1` | 本猜实际声韵全拼反馈的惊讶度；末盘是自信息，中前盘是事件级平滑代理量 |
| `I2` | 本猜实际声调反馈的自信息 |
| `J` | 本猜前累计的已知 `I1+I2`，缺失时是下界 |
| `N_I` | `initialRows` 中不同声母四元组数量 |
| `N_F` | `finalRows` 中不同韵母四元组数量 |
| `N_eff` | `ifPyRows` 中全拼四元组分布的熵有效数量 |
| `r` | 玩家超过固定 1000 基准样本中多少比例的原始百分位 |
| `r'` | 信息饱和压缩后的最终百分位 |

### 2.6 失败分支

| 情况 | 常规 `E`/排名 | 特殊评级 | 实际信息与后验 |
|---|---|---|---|
| V3 有虚拟粒子 | 正常 | 正常检查 | 正常计算 |
| 虚拟池零接受，但 `ifPyRows` 非空 | 退回全真实粒子，正常排名 | 正常检查 | 正常计算或按零命中规则处理 |
| V3 无法形成任何粒子 | 暂停，不产生普通评级 | 若触发仍可成为本猜评级 | `I1` 记缺失；`I2` 仍计算；后验仍过滤 |
| 末盘搜索超过节点/候选预算 | 暂停，不使用部分枚举 | 若触发仍可成为本猜评级 | `I1` 记缺失；`I2` 仍计算；后验仍过滤 |
| 末盘约束矛盾 | 与超预算相同 | 若独立后验仍有效，特殊评级仍可能存在 | 继续按实际反馈更新独立后验 |
| 声母、韵母或声调独立后验变空 | 本轮会话标为无效，不显示评级 | 也不显示 | 需要检查拼音约定、反馈或状态损坏 |

某轮缺少 `I1` 或 `I2` 时，`missingI1`/`missingI2` 增加，后续 `J` 是已知下界。当前声调权重、百分位压缩和特殊评级全部使用这个同一个保守下界，不会猜测缺失信息。

## 3. 为什么不能用更简单的评分

### 3.1 满足全部反馈不总是最佳信息猜测

假设 Wordle 已知答案是 `_ound`，候选为 `found/hound/mound/sound/wound`。逐个猜候选平均需要三猜，而用一个同时覆盖 `h/m/s/w` 的探测词，下一猜即可确定答案。

汉兜同理：把已知绿色放回原位通常不会继续分割可能空间；移动红色、覆盖高频新元素可能更有价值。因此中前盘常见的好猜测会：

- 避免重复查询已经确定为灰色的元素；
- 将红色元素移到尚未排除的位置；
- 避免无意义地重复绿色信息；
- 用剩余槽位覆盖高频新元素。

但这些只是人类直觉，不能直接写成“移动一个红色加几分”。当前算法让完整反馈分布自然决定它们的价值。

### 3.2 同一元素的多个查询不是独立事件

假设已知一个 `sh` 只可能在第 2、3、4 位且三者等概率。在第 2、3 位同时查询 `sh`，反馈只有：

- 绿、灰；
- 灰、绿；
- 红、灰。

三种等概率反馈直接确定位置，信息为：

\[
\log_2 3\approx1.585\text{ bit}
\]

它不是一个 `sh` 的信息乘二。四位置联合反馈编码统一处理一个、两个、三个或四个重复元素，不需要枚举特例。

### 3.3 全拼不是第三个独立维度

全拼由声母和韵母的配对决定。分别知道一个 `b` 和一个 `ao`，不等于知道它们连接成 `bao`。全拼反馈提供的正是连接关系。

因此不能计算：

\[
H(F_I)+H(F_F)+H(F_{full})
\]

这会重复计算共享信息。当前算法计算三者的联合熵。

### 3.4 真实候选为 1 不代表逻辑信息饱和

首猜后，满足声母、韵母、全拼全部反馈的真实成语经常只剩个位数；但独立声母、韵母后验可能仍然很大。若只使用真实候选：

- 大量仍能查询 `r`、`er`、`c` 等未知元素的猜测会得到 `E1=0`；
- 评分会依赖词典是否刚好收录某个罕见组合；
- 算法会比人类早很多轮“知道答案”。

V3 虚拟粒子和末盘完整拼音组合就是为了解决这个结构性问题。

## 4. 反馈编码

### 4.1 单维四位反馈

每个位置使用三进制数字：

- `none = 0`；
- `misplaced = 1`；
- `exact = 2`。

四位反馈编码为：

\[
c=s_0+3s_1+9s_2+27s_3
\]

所以单维共有 `3^4=81` 个编码。

编码器执行：

1. 找出全部绿色，并占用对应答案位置；
2. 对剩余猜测从左到右寻找第一个未占用的相同答案元素；
3. 找到则红，否则灰。

这个顺序同时用于声母、韵母、全拼和声调。

### 4.2 全拼编码

一个完整音节 ID 由 `(initialId, finalId)` 组成。全拼匹配比较这对 ID，而不是把声母、韵母分开比较；所以 `b+ao` 与 `b+o`、`p+ao` 都不同。

全拼同样使用绿色优先、剩余查询从左到右匹配的四位反馈算法。

### 4.3 零声母

`安 an`、`恩 en`、`而 er` 等音节的声母类别是 `NULL_INITIAL_ID`。它是答案槽位中的合法类别，但 UI 没有一个可见的“空声母方块”，因此玩家猜零声母时不能凭空获得声母反馈。

实现方式是：

- 该位置在声母反馈编码中固定写入三进制 `0`；
- 这个 `0` 数值上与 `none` 相同，语义上却是“没有查询”；
- 它不会占用答案中的零声母槽位；
- 它永远不会产生红色或绿色声母信息；
- 韵母和全拼维度仍然正常评分。

例如猜测和假想答案第一字都是 `安 an`：声母码第一位仍为 `0`，韵母 `an` 和完整音节 `an` 可以为绿色。算法通过猜测元组中的 `NULL_INITIAL_ID` 知道这里是跳过，而不是一个真正的灰色声母查询。

### 4.4 联合反馈码与加权熵

声母、韵母、全拼联合码为：

\[
c_{joint}=c_I+81c_F+81^2c_{full}
\]

理论上有 `81^3=531441` 个桶。

对每个假设计算联合码，将该假设的概率质量加入对应桶。若桶质量归一化后为 `p_b`，则：

\[
E_1=-\sum_b p_b\log_2p_b
\]

V3 粒子等质量，因此桶质量就是粒子数；末盘候选带显式 `Float64` 权重，因此桶质量是权重之和。实现复用一个大桶数组，并只清理本轮访问过的桶，避免重复初始化 531441 个位置。

## 5. 后验状态及字段职责

### 5.1 独立后验

`EvalState` 的三个主要后验都是 44010 行语料的行索引：

| 字段 | 保留条件 | 用途 |
|---|---|---|
| `initialRows` | 满足全部声母历史反馈 | V3 声母来源、末盘触发规模、状态有效性 |
| `finalRows` | 满足全部韵母历史反馈 | V3 韵母来源、末盘触发规模、状态有效性 |
| `toneRows` | 满足全部声调历史反馈 | `E2` 样本和精确 `I2` |

它们故意分别过滤。即使只有一条真实成语同时满足全部条件，也不能把三个独立后验提前相交成一条。

语料行默认等权。同一个声母四元组、韵母四元组或声调四元组若由很多成语共享，就以重复行的形式获得更大质量。

### 5.2 `ifRows` 与 `ifPyRows`

这两个字段名称来自 V2.1 诊断阶段，但当前职责并不相同：

| 字段 | 精确定义 | 当前唯一用途 |
|---|---|---|
| `ifRows` | 同一真实语料行同时满足声母和韵母反馈 | 仅用于开发诊断、规模和收缩轨迹；不生成 V3 真实粒子，不计算 `I1` |
| `ifPyRows` | 同一真实语料行同时满足声母、韵母和全拼反馈 | V3 真实粒子来源、`N_eff`、V3 实际信息的 `p_real` 回退以及诊断 |

生产 Worker 始终维护这两个集合。`EvalDiagnosticsState` 这个类型名是历史遗留；其中 `ifPyRows` 和 `pinyinHistory` 已经是 V3 的生产依赖，不再只是开发模式信息。非开发环境只是不把完整诊断快照传回主线程。

表中的“满足反馈”始终指满足**已经提交并处理完的历史反馈**。评价当前猜测时，`ifPyRows` 仍是本猜之前的集合；第 7 节以它为分母计算本轮实际反馈概率。只有在本猜评分、`I1/I2` 计算结束后，才把本轮反馈加入历史并过滤这些集合。若先过滤，实际反馈在新集合中的比例会被错误地抬高，极端情况下会恒为 1。

集合为空时：

- `ifRows` 为空：没有语料行同时满足独立声母和韵母反馈；在正常支持的谜底必在语料中的不变量下，这是解析、反馈或恢复异常，但独立后验仍可能各自非空；
- `ifPyRows` 为空：没有语料行满足三种拼音反馈，同样属于防御性异常。V3 仍可尝试完全依靠虚拟粒子评分，但 `I1` 的语料回退不可用；
- 独立的 `initialRows`、`finalRows` 或 `toneRows` 为空：`EvalState.valid=false`，这是会话无效，而不只是词库稀疏。

### 5.3 历史

状态还保存：

- `history`：声母、韵母、全拼查询元组及反馈码，供末盘约束搜索；
- `visibleHistory`：包括汉字和声调在内的完整可见历史，供 `matchesAllFeedback()` 重放；
- `pinyinHistory`：全拼查询及反馈，供 V3 虚拟粒子过滤；
- 三个独立后验的历史哈希与全拼历史哈希，供确定性随机种子；
- 累计 `I1`、`I2` 和缺失次数。

### 5.4 汉字信息的准确边界

当前普通概率模型完全不使用汉字反馈：

- 汉字不进入 `E1` 或 `E2`；
- 汉字不进入 `I1` 或 `I2`；
- `J` 因此不包含汉字信息；
- 汉字反馈不筛选 `initialRows`、`finalRows`、`ifRows`、`ifPyRows` 或 `toneRows`。

汉字只用于两处离散规则：

- `matchesAllFeedback()` 检查候选是否重放全部历史反馈；
- 本轮四个汉字都为绿色时判定 `won=true`。

## 6. 中前盘 V3 混合粒子

当 `N_I×N_F>32` 时使用 V3。V3 生成固定 4096 个最终等质量粒子，玩家和 1000 个基准词共享这同一批粒子。

可以先把 V3 理解成以下过程：真实语料仍然充足时，主要相信满足全部拼音反馈的真实成语；真实联合后验因词库稀疏而变小时，从分别仍然丰富的声母、韵母后验中重组出“发音合法、历史一致”的虚拟四音节组合。虚拟组合再按真实音节搭配频率和重复结构校准。它们不需要语义上像成语，只需要让反馈统计不要因为词库稀疏而过早坍缩。

本节沿用实现中的 `real` 命名，但“真实粒子”和 `p_real` 都只表示**语料支持的粒子/频率**，不是已知的真实谜底。阅读时也可把它们理解为“语料粒子”和“语料概率”。

### 6.1 有效假设数 `N_eff`

`ifPyRows` 可能有很多语料行，但其中许多行共享相同的全拼四元组。先按 `(initialTuple, finalTuple)` 合并。若四元组 `x` 出现 `count_x` 行，则令归一化行频率

\[
p_x=\frac{count_x}{|ifPyRows|},\qquad \sum_xp_x=1
\]

再定义：

\[
N_{eff}=2^{-\sum_xp_x\log_2p_x}
\]

它是熵对应的“等权假设数量”。例如 100 行都同音时 `N_eff=1`；100 个等频全拼四元组时 `N_eff=100`。

### 6.2 真实/虚拟数量

真实占比为：

\[
\lambda=\frac{N_{eff}}{N_{eff}+32}
\]

它控制最终数组中的粒子**数量**：

\[
n_{real}=\operatorname{round}(4096\lambda),\qquad
n_{virtual}=4096-n_{real}
\]

若 `ifPyRows` 为空，`n_real` 强制为 0。真实粒子从 `ifPyRows` 的语料行均匀抽取：

- 行数不少于目标数量时使用 reservoir sampling；
- 行数更少时有放回抽取；
- 同音成语对应不同语料行，所以自然形成更大频率质量；
- 没有额外的“真实粒子权重”。

这里的 `32` 可以理解为虚拟模型相对真实联合后验的一个经验伪计数。它使切换连续：真实后验丰富时更信任语料，稀疏时逐步增加虚拟质量。

### 6.3 虚拟候选的提议分布

先从 `initialRows` 和 `finalRows` 分别确定性抽样至多 4096 个四元组。超过 4096 行时使用由历史哈希派生种子的 reservoir sampling；因此刷新后样本不变。

每次候选尝试分别随机取一个声母四元组和一个韵母四元组，将它们重新配对。这个提议分布保留了独立历史反馈和语料行频率，但暂时假设声母、韵母独立。

候选必须满足：

1. 四个 `(声母, 韵母)` 都是 396 种语料支持的合法音节之一；
2. 完整音节四元组重放全部历史全拼反馈时完全一致。

### 6.4 声韵耦合权重

令：

- `C(i,f)`：176040 个语料槽位中音节 `(i,f)` 的次数；
- `C_I(i)`：声母 `i` 的槽位次数；
- `C_F(f)`：韵母 `f` 的槽位次数；
- `S=176040`。

单槽声韵耦合比为：

\[
Q(i,f)=\frac{C(i,f)S}{C_I(i)C_F(f)}
\]

若声母、韵母独立，`Q≈1`；现实中搭配比独立模型更常见时 `Q>1`，更少见时 `Q<1`。非法组合因 `C(i,f)=0` 已在上一步淘汰。

一个虚拟四元组的未归一化权重为：

\[
u(x)=\left(\prod_{j=1}^{4}Q(i_j,f_j)\right)R_{V3}(signature(x))
\]

`R_V3` 修正声母、韵母和全拼重复结构，生成方式见第 13 节。实现累加对数权重，最后减去最大对数再指数化，避免浮点上溢/下溢。

### 6.5 候选池、系统重采样与重复粒子

如果需要虚拟粒子，目标候选池大小为：

\[
\min(16384,\max(4096,4n_{virtual}))
\]

最多尝试 262144 次。处理规则是：

- 接受数达到目标池大小即停止；
- 未达到目标但至少有一个合法候选时，仍使用已有池；
- 将 `u(x)` 归一化后做一次加权系统重采样，允许有放回，补足恰好 `n_virtual` 个粒子；
- 系统重采样可理解为在 `[0,totalWeight)` 上等距放置 `n_virtual` 个点，只随机选择第一个点，比每次独立抽签方差更低；
- 重采样后不再保留显式权重，每个输出粒子质量相同，原权重由重复次数表示。

真实粒子、虚拟粒子以及两者之间若得到相同四元组，都**不会合并**。相同粒子的多次出现就是该假设的经验概率质量。最后使用同一历史种子确定性洗牌，避免数组前半段永远是真实粒子。

如果 262144 次尝试后一个虚拟候选都没有：

- `ifPyRows` 非空：将 4096 个位置全部改为真实粒子并标记 `fallback=true`；
- `ifPyRows` 也为空：V3 无可用粒子，普通评价暂停。

### 6.6 V3 的熵分布

最终 4096 个粒子等质量：

\[
P(X_{PY}=x)=\frac{\text{x 在数组中的出现次数}}{4096}
\]

对每个猜测计算全部粒子的联合反馈码，桶中的粒子比例就是反馈概率。加权只发生在虚拟候选重采样之前；熵阶段不再次乘耦合或结构权重。

## 7. V3 的 `I1` 工程估计与零命中

### 7.1 两种概率估计

本轮真实联合反馈码记为 `f`：

- `n_particle`：4096 个 V3 粒子中反馈为 `f` 的数量；
- `n_corpus`：**本猜之前**的 `ifPyRows` 中反馈为 `f` 的语料行数。

两种概率为：

\[
p_{particle}=n_{particle}/4096,\qquad
p_{real}=n_{corpus}/|ifPyRows|
\]

`p_real` 按真实语料行等权，不使用 V3 虚拟权重。多条同音成语仍通过重复行增加质量。

粒子命中较多时，经验粒子概率更能表示 V3 模型；命中很少时，4096 样本的离散误差过大，所以向完整真实联合后验平滑回退。

### 7.2 平滑公式

令：

\[
x=\operatorname{clamp}(n_{particle}/8,0,1)
\]

具体的 smoothstep 为：

\[
\alpha=x^2(3-2x)
\]

混合概率：

\[
p=(1-\alpha)p_{real}+\alpha p_{particle}
\]

于是：

\[
I_1=-\log_2p
\]

边界含义：

- `n_particle=0`：`α=0`，完全使用 `p_real`；
- `n_particle≥8`：`α=1`，完全使用粒子概率；
- `1≤n_particle≤7`：平滑过渡。

这里的 `α` 由**当前实际反馈事件自己的粒子命中数**决定。因此上式是便宜、稳定的事件级概率估计，不是把两个完整概率分布用同一个全局系数混合；把所有可能反馈都代入后，所得 `p` 不保证总和为 1。这正是第 2.3 节把中前盘 `I1` 称为惊讶度代理、把累计 `J` 称为模型化约束量的原因。该近似被接受，是因为 `J` 只通过缓慢的产品曲线影响后续评分；猜前排名 `E1` 仍严格使用归一化的 4096 粒子反馈分布。

### 7.3 未定义分支

实现不会把 `p=0` 解释成无穷信息。以下任一情况都会令本猜 `I1` 未知并增加 `missingI1`：

- `ifPyRows` 为空；
- `n_corpus=0`，即语料联合后验也没有观察到该反馈；
- V3 粒子或反馈统计不可用；
- 混合概率不是正的有限数。

即使 `n_particle>0`，只要 `n_corpus=0`，当前实现仍不采用纯粒子概率，而是把 `I1` 标为缺失。在合法谜底应保留于语料的前提下，这表示真实联合后验、拼音解析或恢复状态已经不一致，而不是一次正常的“极罕见反馈”。反馈仍会推进独立后验，`J` 以后作为下界使用。

## 8. 末盘完整拼音后验

### 8.1 切换条件和目的

令 `N_I`、`N_F` 分别为独立后验中不同声母、韵母四元组的数量。满足：

\[
N_I\times N_F\le32
\]

时使用末盘模型。

这不是“真实答案已经确定”的声明，而是经验上 V3 粒子在该区域容易系统性漏掉仍然合法的拼音组合。此时直接完整枚举公开反馈允许的音节组合，比分布采样更可靠。

### 8.2 末盘先验

对 396 种合法音节定义全局频率：

\[
q(s)=C(s)/176040
\]

候选四元组 `x=(s1,s2,s3,s4)` 的原始权重为：

\[
W(x)=\left(\prod_{j=1}^{4}q(s_j)\right)R_{endgame}(signature(x))
\]

这里只使用音节频率和末盘专用重复结构修正：

- 不要求四元组出现在真实成语库中；
- 不使用位置专属频率；
- 不再次乘 V3 的声韵耦合比，因为 `q(s)` 已经是联合音节频率；
- 不复用 V3 结构权重，因为两套基础提议分布不同。

完整搜索成功后归一化：

\[
P(x)=W(x)/\sum_{x'}W(x')
\]

`E1` 和实际 `I1` 都按这个概率质量计算。

### 8.3 约束搜索

从历史反馈为声母、韵母、全拼分别建立：

- 各位置固定值；
- 各位置禁止值；
- 每个元素最少出现次数；
- 每个元素最多出现次数。

搜索只给每个位置分配 396 种合法音节之一，并采用：

- 约束传播；
- 数量上下界剪枝；
- 优先展开候选最少的位置；
- 生成完整四元组后再调用精确反馈编码器重放全部历史。

最后一步保证剪枝规则即使遗漏了某种重复元素细节，也不会接受错误候选。零声母在声母约束中仍按“无查询”跳过。

### 8.4 “完整”与预算的精确定义

固定上限为：

- 最多访问 262144 个搜索节点；
- 最多保留 4096 个完整候选。

成功的定义是：

> 深度优先搜索在没有触发任一上限的情况下遍历完全部分支，并找到至少一个候选，即 `status === 'complete'`。

边界行为：

- 正好找到 4096 个候选且之后完整结束，可以成功；
- 一旦发现第 4097 个候选，立即返回 `candidate-limit`；
- 一旦还需访问新节点但已达到 262144，返回 `node-limit`；
- 所有分支结束仍没有候选，返回 `contradiction`。

任何非 `complete` 状态都会丢弃已发现的全部部分候选，并返回空后验。部分枚举的概率质量取决于搜索顺序，不能用于评分。

### 8.5 搜索失败后的游戏行为

搜索失败时：

- 不计算普通 `E1/E/基准百分位`；
- 如果本猜满足全部历史反馈或猜中，仍可显示第 11.4 节的特殊评级下限；
- `I1` 标记缺失；
- `I2` 仍从完整声调后验计算并累计；
- 声母、韵母、全拼、声调历史仍正常推进；
- 下一猜重新根据更新后的状态尝试模型构造。

如果更新后任一独立后验为空，会话才被标为无效并停止显示评价。

在“合法谜底必在语料、反馈编码一致”的正常不变量下，完整搜索得到 `contradiction` 本身不应发生：真实答案的拼音至少应构成一个候选。该状态主要用于防御解析约定、恢复数据或约束实现不一致。实现不会让末盘搜索器单独宣布整个会话无效；它仍推进各独立后验，并允许不依赖普通模型的特殊评级先行生效。若随后的独立后验也变空，才统一将会话标为无效。

## 9. 声调模型与累计信息

### 9.1 独立声调后验

声调四元组来自 44010 条语料，历史反馈使用相同的四位置重复匹配算法过滤 `toneRows`。

- `E2`：`toneRows` 不超过 4096 条时全部使用，否则确定性 reservoir sampling 4096 条；样本等质量；
- `I2`：不使用样本，遍历完整 `toneRows`，以真实反馈命中行数除以后验总行数。

若本轮实际声调反馈在猜前 `toneRows` 中零命中，则 `I2` 不取无穷，而是记为缺失并增加 `missingI2`。随后按同一反馈过滤会使 `toneRows` 变空，`EvalState.valid=false`，因此会话停止显示后续评级。这与 `I1` 的虚拟模型容错不同：声调没有另一套虚拟后验可继续接管。

声调暂时不与声母、韵母或全拼联合。模型不知道例如某个音节只支持特定声调；这是有意近似。

### 9.2 声调权重

令 `J` 为本猜前累计约束量，声调权重为：

\[
w(J)=0.5+0.5\operatorname{clamp}\left(\frac{J-10}{10},0,1\right)
\]

即：

- `J≤10`：`w=0.5`；
- `10<J<20`：线性增加；
- `J≥20`：`w=1`。

含义是：盘面信息较少时，声调以后仍有很多机会顺便确定；进入收束阶段后，声调逐渐成为完整答案的重要瓶颈。

声调权重只影响期望质量 `E`，不影响实际公开信息 `I2`。

### 9.3 信息缺失时的下界

`J` 只累加成功计算的 `I1` 和 `I2`。若某轮缺失，`informationIsLowerBound=true`。

现行实现没有估算缺口，后续三类产品规则都使用这个同一个下界：

- 声调权重 `w(J)`；
- 信息饱和压缩；
- 满足历史反馈/猜中的特殊评级。

这样比较保守且可复现，但它不表示真实累计约束恰好等于显示值。

## 10. 基准样本、百分位与普通评级

### 10.1 固定 1000 词基准

生成脚本使用固定种子 42，对 44010 个语料**行索引**做无放回均匀抽样，取 1000 行：

- 不是从当前后验抽样；
- 不是从当前“合理答案”抽样；
- 不是遍历全部合法猜测后的精确全局排名；
- 当前 44010 行的成语文字互不重复，因此当前基准词也不重复；若未来语料出现重复行，行级抽样会保留该频率语义。

本文称结果为**基准样本百分位**，不能简称为“全体猜测百分位”。1000 是速度、稳定性和分辨率之间的工程折中。

始终从全语料而不是当前候选取基准，原因是普通模式允许探测性猜测。若只与满足反馈的候选比较，会系统性排除移动红色和覆盖新元素的策略，而且不同轮次的参考集合会改变含义。固定样本提供稳定标尺；当前历史已经通过后验模型改变每个基准词的 `E`。

### 10.2 排名

对玩家和每个基准词使用同一批：

- V3 粒子或末盘后验；
- 声调样本；
- 声调权重 `w(J)`。

基准总分预先排序。令严格低于玩家 `E` 的基准数为 `k`：

\[
r=k/1000
\]

同分不算超过，实现使用 strict lower bound。原始分数不会先四舍五入。

### 10.3 信息饱和压缩

纯信息熵会在约束已经很充足时继续奖励铺新元素。定义：

\[
t=\begin{cases}
1,&N_I\times N_F\le32\\
\operatorname{clamp}\left(\frac{J-23}{7},0,1\right),&N_I\times N_F>32
\end{cases}
\]

只压缩高于 Good 分界的百分位：

\[
r'=\begin{cases}
r,&r\le0.70\\
(1-t)r+t\times0.701,&r>0.70
\end{cases}
\]

所以：

- `Average`、`Mistake`、`Incorrect` 不因信息充足继续下降；
- 中前盘 `J=23→30` 时，高分平滑压向 `0.701`；
- 进入末盘触发区后，高于 0.70 的结果直接压到 `0.701`；
- `0.701` 有意落在 Good 区间内，不会因压缩变成 Average。

### 10.4 六档普通评价

所有边界使用严格 `>`：

| 压缩后基准样本百分位 `r'` | 评价 |
|---:|---|
| `>0.99` | Brilliant / 绝妙 |
| `>0.90` | Excellent / 优秀 |
| `>0.70` | Good / 不错 |
| `>0.50` | Average / 一般 |
| `>0.30` | Mistake / 失误 |
| 其余 | Incorrect / 错误 |

例如 `0.70` 是 Average，`0.701` 是 Good；`0.90` 是 Good，必须大于 `0.90` 才是 Excellent。

## 11. 满足历史反馈和猜中的特殊评级

### 11.1 `matchesAllFeedback()` 检查什么

函数把当前猜测当作一个**假想答案**，对本猜之前的每一条 `visibleHistory` 重新调用游戏反馈算法，并要求六个内部字段全部相同：

- 汉字 `char`；
- 游戏当前输入模式的三个拼音显示部件 `_1/_2/_3`；
- 全拼 `py`；
- 声调 `tone`。

这六个字段与第 1.1 节的映射相同。在标准拼音模式中，`_1` 通常是声母、`_2` 是韵母、`_3` 为空；双拼和注音可以有不同的显示部件拆分。这里有意调用游戏 `testAnswer()` 比较原始可见反馈，而不是拿评价器的规范声母/韵母 ID 近似替代它。

这里重放的只有提交前历史，不包含本轮刚得到的 `actualFeedback`。它检查的是“这个词能否成为此前所有公开反馈的答案”，不是严格模式的输入合法性规则。

### 11.2 为什么需要特殊规则

普通信息熵常常不鼓励重复已知绿色；但在约束足够多后，能够找到一个满足全部反馈的真实成语，通常意味着玩家正在合理收束，而不是浪费查询。

另一方面，信息越充分，找到满足全部反馈的词越容易，所以特殊评级下限会随 `J` 增大而降低：

- 刚跨过收束起点时，这种尝试罕见且可给 Brilliant；
- 中后期它逐渐成为正常行为，只保证 Excellent 或 Good；
- 信息很少时不额外奖励，以免第二猜随便撞到一个兼容词就获得高评价。

### 11.3 评级下限

| 猜前 `J` | 满足全部历史反馈的评级下限 |
|---:|---|
| `J≤13` | 无，使用普通评级 |
| `13<J<23` | Brilliant |
| `23≤J<26` | Excellent |
| `J≥26` | Good |

`13`、`23`、`26` 处的跳变是有意的离散产品规则，不是连续概率模型推导出的结论。

### 11.4 猜中

如果本轮四个汉字反馈都是绿色，则 `won=true`：

- `J≤13` 时至少为 Brilliant；
- `J>13` 时沿用上表相应下限。

最终评级取普通评级和特殊下限中较高者。特殊规则只能抬高，不能压低普通评级。

若普通模型本轮不可用，但独立后验更新后仍有效，特殊评级可以单独成为徽章；若没有特殊评级，则该猜不显示徽章。

## 12. 经验常数与“客观”的准确含义

本文所说“尽量客观”，准确含义是：

> 不对单个灰、红、绿以及“移动一个红色”“查询一个新元素”等动作手工加减固定分值，而让统一反馈概率模型产生连续分数。

它不表示系统没有经验参数。先验选择、近似规模、切换点和产品分档仍需要人工决定。

| 常数 | 作用 | 主要来源 |
|---|---|---|
| 1000 个基准词 | 基准样本百分位 | 排名稳定性与运行时间折中 |
| 4096 个粒子/后验样本 | 限制每词反馈计算量 | 性能预算、2 的幂便于固定规模实现 |
| 16384 虚拟池 | 给加权重采样留出多样性 | 最终粒子数的最多四倍 |
| 262144 次尝试/节点 | 防止极端约束长时间占用 Worker | 确定性性能预算 |
| `N_eff+32` | 控制真实/虚拟混合速度 | 词库稀疏诊断和试玩校准，不是统计定理 |
| 8 次命中 | `I1` 从真实后验过渡到粒子概率 | 小样本稳定性经验线 |
| `N_I×N_F≤32` | 切换末盘完整模型并完全压缩高分 | V3 末盘系统性漏项出现区间 |
| `w` 的 10、20 | 声调权重从 0.5 增至 1 | 玩法节奏和试玩校准 |
| `J` 的 23、30 与 0.701 | 高分饱和压缩 | 产品策略和试玩校准 |
| 特殊评级的 13、23、26 | 收束难度分段 | 产品策略和试玩校准 |
| `[1/16,16]` | 结构校准权重截断 | 防止稀有签名支配分布 |

这些常数中，4096、16384、262144 主要控制复杂度；其余多数影响评分语义。修改任何会改变最终数值或评级的常数，都应增加测试并升级 `EVAL_VERSION`。

## 13. 预处理数据与校准

数据由 `scripts/generate-eval-data.mjs` 从 `playground/idioms.jsonl` 生成到 `src/eval/data.ts`。

### 13.1 语料和紧凑表示

当前生成数据包含：

- 44010 条互不重复的成语语料行；
- 176040 个音节槽位；
- 24 类声母，包括零声母；
- 34 类韵母；
- `24×34=816` 个理论声韵对中的 396 种语料支持音节；
- 声母、韵母、声调四元组；
- 音节、声母、韵母全局频数；
- V3 和末盘各自的结构修正表；
- 固定 1000 个基准词。

声母 ID 用 5 bit、韵母用 6 bit、声调用 3 bit，四个位置打包为 `uint32`。typed array 以小端 base64 写入生成文件，运行时按需解码。

生成器会按运行时相同规则重新拆分拼音，并验证 `y/w`、零声母和多音字数据约定，防止生成数据与游戏反馈不一致。

现行规范拆分采用拼音书写形式，而不是重新解释成音系学上的介音：`y`、`w` 是可见声母类别，例如 `yan=y+an`、`wu=w+u`；`an`、`en`、`er` 等没有前缀的音节使用 `null+an`、`null+en`、`null+er`。韵母中的 `v/ve` 表示 `ü/üe` 的数据写法。声调取值为 `0..4`，其中 `0` 是轻声/未标普通四声，`1..4` 是四个声调。这套规范 ID 与第 1.1 节的 `_1/_2/_3` 显示部件不是同一个接口。

### 13.2 重复结构签名

结构签名不记录具体元素，只记录四个位置之间的相等关系，例如：

- 哪些声母相同；
- 哪些韵母相同；
- 哪些完整音节相同。

它用于修正“独立重配后重复元素太多或太少”的偏差。

### 13.3 V3 结构修正

生成器固定种子随机重配一百万组真实声母/韵母四元组。每个合法重配的权重为四个第 6.4 节声韵耦合比之积。对签名 `s` 定义：

\[
P_{real}(s)=\frac{C_{real}(s)}{44010}
\]

\[
u_Q(x)=\prod_{j=1}^{4}Q(i_j,f_j),\qquad
M_{base}(s)=\sum_{x:\,signature(x)=s}u_Q(x),\qquad
P_{base}(s)=\frac{M_{base}(s)}{\sum_{s'}M_{base}(s')}
\]

这里求和只包含一百万次尝试中音节全部合法、权重为正且有限的重配。令这些合法重配的次数为 `N_valid`，修正权重精确为：

\[
R_{V3}=\operatorname{clip}\left(
\frac{P_{real}+1/44010}{P_{base}+1/N_{valid}},
1/16,16
\right)
\]

`1/44010` 和 `1/N_valid` 是现行实现使用的经验平滑尺度。后者不是把一个非加权计数直接加入 `M_base`，而是明确加在已归一化的 `P_base` 上；写出这一区别是为了避免维护时把带权基础质量误实现成普通命中次数。

运行时不直接把这张表归一化；它与四个 `Q(i,f)` 相乘形成虚拟候选的相对权重，系统重采样时统一除以总权重。

### 13.4 末盘结构修正和“轨道等价类”

末盘基础模型直接独立抽四个音节 `q(s)`，与 V3 的重配模型不同，所以必须单独校准。

为了坚持“不使用位置专属先验”，若两个结构签名仅仅是把四个位置整体重新排列后得到，就将它们归入同一个**位置排列等价类**，代码中称为 orbit。比如“第 1、2 位重复”和“第 3、4 位重复”在结构上等价。

第 8.2 节简写的 `R_endgame(signature(x))` 实际包含一步 `signature → orbit` 映射；末盘校准表和运行时查找的键都是 orbit，而不是带方向的原始签名。

生成器：

1. 将真实语料签名按位置排列等价类聚合；
2. 固定种子从全局音节槽位独立抽取一百万个四元组，估计末盘基础分布；
3. 分子、分母各加一个样本后取真实/基础比；
4. 将权重截断到 `[1/16,16]`。

若 orbit `o` 在真实语料中有 `C_real(o)` 行，在一百万次基础抽样中出现 `C_base(o)` 次，则生成器实际计算：

\[
R_{endgame}(o)=\operatorname{clip}\left(
\frac{(C_{real}(o)+1)/44010}{(C_{base}(o)+1)/1000000},
1/16,16
\right)
\]

运行时未覆盖的 orbit 使用 `1/16`，不会把任何合法四音节组合的概率直接置零。

## 14. Worker、恢复与持久化

### 14.1 为什么预计算下一猜

一次评分的主要耗时不是玩家词本身，而是计算 1000 个基准词的信息熵。上一猜反馈确定后，下一猜的后验、声调权重和全部基准分数已经确定，不必等玩家提交。

Worker 会提前执行：

- 构造 V3 粒子或末盘后验；
- 抽样声调后验；
- 计算 1000 个基准词的 `E1`、`E2`、`E`；
- 排序 1000 个 `E`。

玩家提交后只计算玩家词并二分排名。若玩家在预计算完成前提交，请求会在 Worker 内串行等待；页面输入和其它按钮仍由主线程响应，评级稍后异步出现。

虽然徽章在提交后出现，普通评级需要的模型、权重和基准排序都来自提交前状态；本轮真实反馈只用于随后计算 `I1/I2`、判断猜中和更新后验。因此实时显示不会把未公开谜底信息反向注入普通分数。

### 14.2 两阶段接口

- `prepareEvaluation(state)`：构造本轮模型、声调样本和可选基准排序；
- `advancePreparedEvaluation(...)`：计算玩家分数与实际信息，评级，然后更新状态；
- `evaluate()`、`advanceEvaluation()`：测试和非 UI 场景的同步包装。

### 14.3 会话隔离

会话 key 包含游戏模式和答案。每日、随机、自定义之间切换，或同长度残局内容变化时，会终止旧 Worker 并创建新会话。

主线程同时检查：

- `sessionId`；
- 游戏 key；
- 猜测索引；
- 猜测文字。

旧 Worker 的迟到消息不会写入新游戏。

### 14.4 恢复与持久化

评级保存在 `TriesMeta.ratings`，版本保存在 `ratingsVersion`。当前版本为 5。

- 新猜测先写入 `null`；
- 有未完成 Worker 任务时不写有效版本；
- 全部已提交猜测都得到结果后才写入版本 5；
- 旧版本会逐猜重算；
- 已是版本 5 时，可以跳过历史 1000 词排名，但仍必须逐猜恢复 `I1/I2`、过滤后验并准备下一猜；
- 显示开关只隐藏徽章，不能停止状态重建；
- Worker 连续启动失败时，本局禁用评价，不回退到可能阻塞 UI 的主线程同步计算。

`ratings` 中的 `null` 有两种可能含义：任务尚未完成，或任务已经完成但普通模型和特殊规则都没有产生徽章。活动会话用内存中的待处理索引集合区分二者；持久化后则用版本区分：`ratingsVersion=5` 且长度一致时，数组中的 `null` 是一个已经完成的“无徽章”结果；版本缺失或不匹配时，`null` 只能视为待算或旧结果。所以上述“全部得到结果”包含结果为 `null` 的已完成任务。

“Worker 连续启动失败”的精确策略是：第一次启动或运行失败后，以同一游戏和猜测序列新建一次会话并重试；第二次连续失败后设置本局禁用标志、清除有效 `ratingsVersion`，不再重试，也不转到主线程计算。开始新的评价会话时失败计数重置。

## 15. 算法迭代过程

这一节记录为什么会有当前结构。以下旧版本只用于理解，不再参与生产双轨评分。

### 15.1 初始方案：真实候选集信息熵

最直接的方法是保留所有满足完整历史反馈的真实成语，对猜测统计反馈分布。它在 Wordle 中自然，但在汉兜中收缩太快：一次猜测包含很多反馈维度，首猜后真实候选经常只有个位数，甚至一条。

当候选只有一条时，任何猜测的候选熵都为 0，但人类通常没有足够信息直接想出那条罕见成语。因此该方案把词库稀疏误当成逻辑确定性。

### 15.2 V1：逐元素独立 MVP

V1 只考虑声母和韵母，把每个元素查询的信息相加，并暂时忽略重复元素、声调、全拼、汉字和声韵约束。

以首猜一个 `sh` 为例：简化语料中 33110 个成语不含 `sh`，10900 个含一个 `sh`，并假设四位置等概率：

\[
P(gray)=33110/44010
\]

\[
P(red)=\frac{10900\times3}{44010\times4}
\]

\[
P(green)=\frac{10900}{44010\times4}
\]

代入三态熵得到约 `1.008 bit`。

V1 计算快，但结构性错误明显：

- 同一元素出现两次被当成两次独立查询；
- 移动红色的价值被低估；
- 连续铺设没猜过的高频元素被重复计算；
- `先来后到`、`瑟调琴弄` 等无视已有红色的猜测可能异常超过所有基准词。

问题不是缺少一个人工红色权重，而是独立事件假设错误。

### 15.3 V2：四位置联合反馈熵

V2 分别维护声母和韵母后验，并计算：

\[
E_{V2}=H(F_I)+H(F_F)
\]

每个 `F` 已经是完整四位反馈码，因此重复元素、多红色和位置移动都由同一个算法处理。V2 完美解决了 V1 的多重元素问题，实测效果显著提高。

但 V2 仍认为声母、韵母独立，并完全忽略全拼连接信息。

### 15.4 V2.1：联合后验诊断

在不改变正式评分的情况下，开发模式曾额外观察：

- `ifRows`：声母+韵母真实联合后验；
- `ifPyRows`：声母+韵母+全拼真实联合后验。

试玩发现词库稀疏很常见：`ifPyRows` 首猜后就低于 10 并不罕见，而独立声母、韵母后验仍很大。真正的独立后验饱和相对更晚。

这证明不能等联合后验恰好为 1 才回退，也不能只使用真实联合成语计算全拼信息。

### 15.5 V3：校准虚拟拼音粒子

V3 将真实 `ifPyRows` 与重新配对的虚拟声韵四元组连续混合，并把声母、韵母、全拼作为一个联合反馈变量。

它先以影子模型与 V2 同时显示。大部分盘面结果接近，少部分声韵连接关键的盘面明显更符合人类判断，因此 V3 后来成为正式中前盘模型，V2 排名代码退出生产路径。

### 15.6 声调和累计约束量

随后加入独立声调熵 `E2` 和实际信息 `I1/I2`。关键约定是：

\[
E=E_1+wE_2,\qquad J=\sum(I_1+I_2)
\]

声调对当前决策的重要性随信息增加，但已经公开的声调反馈本身不能因产品权重而“少算信息”。

### 15.7 零命中平滑

4096 粒子在高信息反馈上可能零命中。直接使用 `1/4096` 会把 `I1` 人为封顶在约 12 bit；直接只用真实后验又回到词库稀疏问题。最终采用 0～8 命中的 smoothstep 混合，只用于实际 `I1`，不改变猜前期望排名。

### 15.8 末盘补全

在 `N_I×N_F` 很小时，V3 会系统性漏掉仍合法的 `er`、`c`、`r` 等查询，导致大量基准词错误得到 `E1=0`。末盘模型改为完整枚举合法音节组合，让移动多个红色和查询新元素继续由联合反馈概率自动衡量。

### 15.9 饱和压缩、收束评级和性能版

最后加入：

- 信息充分时只压缩高于 Good 的基准百分位；
- 满足全部历史反馈和猜中的评级下限；
- Average 第六档；
- 下一猜 Worker 预计算与排序后二分排名。

这些改动形成当前 `EVAL_VERSION=5`。

## 16. 开发诊断

开发模式按猜记录：

- 独立声母、韵母、声调后验行数、不同四元组数和有效数量；
- `ifRows`、`ifPyRows` 行数、不同全拼四元组数和 `N_eff`；
- 每轮后验保留比例；
- V3 或末盘模型、候选数、节点数和搜索状态；
- `E1/E2/E`、单猜与累计 `I1/I2/J`；
- `w`、压缩系数、原始/最终百分位、普通/特殊/最终评级；
- V3 真实/虚拟粒子数、`λ`、接受率、候选/重采样 ESS、非法音节淘汰和结构权重截断；
- 1000 个基准词分数；
- 生成、排名、玩家计算、队列等待和总耗时。

ESS 是 importance sampling 中常用的有效样本量：若未归一化权重为 `u_i`，则：

\[
ESS=\frac{(\sum_i u_i)^2}{\sum_i u_i^2}
\]

权重越集中，ESS 越小。重采样后的诊断则按重复粒子频数计算对应的有效数量。

退化标签：

- `none`：没有明显退化；
- `corpus-sparse`：`ifPyRows` 只剩至多一个不同全拼四元组，但独立后验尚未触发末盘；
- `corpus-saturated`：`N_I×N_F≤32`，表示词库独立后验进入末盘触发区，不表示逻辑上没有未知信息；
- `invalid`：`ifPyRows` 为空的历史诊断标签，更准确的含义是“联合语料不变量异常”。它不必然等于 `EvalState.valid=false`；只要独立后验非空，虚拟模型仍可能防御性地继续工作，但这不表示产品支持谜底位于 44010 行语料之外。

## 17. 当前明确不做的内容

### 17.1 Lucky / Unlucky

不实现。主评价保持猜前决策质量；实际信息只更新后续状态。

### 17.2 汉字概率模型

普通评分不考虑红字或绿字。合理实现需要“全拼→汉字”的条件字频并与拼音联合，收益相对较低、实现和内存成本较高。汉字目前只参与收束检查和猜中判断。

这并不表示汉字反馈永远没有决策价值。例如已知第一位读音为 `tou2` 时，候选汉字可能集中在“头”“投”等少数高频字；再次猜一个“头”开头的成语虽然重复了声母、韵母、全拼和声调，却仍可能区分具体汉字。当前普通模型会漏掉这部分收益。若未来加入，正确方向是建立 `P(汉字 | 全拼及上下文)` 并与拼音反馈联合计熵，而不是给红字、绿字手工加固定分。

### 17.3 声调与拼音的联合先验

声调独立处理，不利用某些声韵组合只支持特定声调的事实。

### 17.4 语义真实的虚拟成语

虚拟粒子追求反馈统计合理，不追求语义上像真实成语。强制它们都是真实成语会重新引入词库稀疏。

### 17.5 位置专属先验

声母、韵母和音节的边际频率都使用四个位置合并后的全局分布，不建立“第一位更常见某音节”之类的元素位置频率。V3 的重复结构签名仍会区分“哪些位置互相重复”；末盘则进一步用位置排列等价类消除这种方向。也就是说，位置无关假设适用于元素边际先验，不应误读为 V3 完全没有任何位置结构。

这一简化来自早期语料实验：声母、韵母和声调在四个位置上的差异被认为足够小，可以换取更稳定、更紧凑的全局先验；汉字位置分布并不满足同样的近似。这也是汉字不能直接照搬当前读音模型的原因之一。它是经验模型选择，不是普通话或成语结构的数学定律。

### 17.6 严格模式专用评价

算法按普通模式的自由探测策略设计，没有衡量严格模式“必须复用提示”的额外约束。严格模式尚未建立独立评价模型。

## 19. 测试重点

当前测试覆盖：

- 绿色优先、红色从左到右、重复元素和零声母；
- 两个相同元素得到 `log2 3` 的数学回归；
- 独立后验和真实答案保留；
- V3 粒子合法性、历史一致性、确定性和分布校准；
- 同音成语增加概率质量但不增加不同假设数；
- 末盘完整性、预算失败和两个真实盘面回归；
- 声调权重、`I1/I2`、百分位压缩及严格边界；
- 满足全部反馈和猜中的特殊评级；
- Worker 预计算与同步路径的数值一致性；
- Worker 排队、模式隔离、失败重试、刷新恢复和版本迁移。

性能目标仍是：1000 个基准词、最多 4096 个拼音假设和 4096 个声调样本的一次准备在目标设备上约 3 秒内完成。这里的“目标设备”是产品预算，不是当前文档已经定义完整的可复现基准机；提交性能结论时应同时记录硬件、浏览器/运行时、生产或开发构建、盘面和计时范围。性能测试不应以改变概率结果为代价。

## 20. 修改算法时必须保持的不变量

下面的标签说明“不变量”来自哪里。`产品` 表示可修改但必须经过明确产品决策和版本升级；`数学/统计` 表示在当前模型语义下不可随意破坏；`游戏规则` 表示必须与玩家看到的反馈一致；`工程` 表示保证异步状态和持久化正确。

1. **[产品] 普通评分必须使用猜前状态。** 本轮真实反馈只能影响 `I`、特殊猜中规则和以后猜测。
2. **[数学/统计] 玩家和基准词共享模型。** 粒子、末盘权重、声调样本与 `w(J)` 必须相同，否则百分位失去可比性。
3. **[游戏规则] 反馈编码必须与游戏一致。** 尤其不能简化重复匹配、输入模式部件和零声母。
4. **[数学/统计] 声母、韵母、全拼必须联合计熵。** 三个熵不能直接相加，否则会重复计算共享信息。
5. **[产品] 实际约束量不乘声调权重。** `E=E1+wE2`，`I=I1+I2`；这是“已公开信息不因当前重视程度而打折”的产品约定。
6. **[产品] 基准百分位使用严格低于。** 同分样本不计入超过数量。
7. **[数学/统计] 末盘搜索失败不能使用部分候选。** 部分后验依赖搜索顺序，不代表目标分布。
8. **[工程] 历史恢复不能只恢复徽章。** 必须重建后验、`J` 和下一猜预计算。
9. **[工程] 随机过程必须由状态派生固定种子。** 刷新、回放和模式切换后结果必须一致。
10. **[当前模型/产品] 汉字不应意外进入普通后验。** 若未来加入，必须设计联合概率模型并升级版本，而不是只在现有分数上随意加权。
11. **[工程/兼容] 改变任何评分数值时升级 `EVAL_VERSION`。** 只有数值完全一致的性能重构可以不升级。

## 21. 接近实现的一轮伪代码

```ts
function prepareTurn(state) {
  const J = state.information.i1 + state.information.i2
  const { initialUnique: NI, finalUnique: NF } = posteriorSizes(state)

  const model = NI * NF <= 32
    ? enumerateCompleteEndgameOrNull(state.history)
    : createMixedV3ParticlesOrNull(state)

  const tones = sampleTonePosterior(state.toneRows, 4096)
  const w = toneWeight(J)
  const compression = NI * NF <= 32 ? 1 : clamp((J - 23) / 7)

  const benchmarkScores = model && tones.length
    ? fixed1000.map(guess =>
        jointPinyinEntropy(guess, model)
          + w * toneEntropy(guess, tones),
      ).sort(ascending)
    : null

  return { model, tones, w, compression, benchmarkScores, J }
}

function submitGuess(state, prepared, guess, actualFeedback) {
  const matchesHistory = replayAllVisibleHistory(guess, state.visibleHistory)
  const won = allCharactersExact(actualFeedback)
  const special = specialRatingFloor(prepared.J, matchesHistory, won)

  let normal = null
  if (prepared.model && prepared.benchmarkScores) {
    const E1 = jointPinyinEntropy(guess, prepared.model)
    const E2 = toneEntropy(guess, prepared.tones)
    const E = E1 + prepared.w * E2
    const raw = strictLowerBound(prepared.benchmarkScores, E) / 1000
    const final = compressAboveGood(raw, prepared.compression)
    normal = ratingFromPercentile(final)
  }

  const I1 = prepared.model
    ? observedPinyinInformationOrNull(state, prepared.model, guess, actualFeedback)
    : null
  const I2 = observedToneInformationOrNull(state.toneRows, guess, actualFeedback)

  const rating = higherRating(normal, special)
  updateInformationAndFilterPosteriors(state, guess, actualFeedback, I1, I2)
  return rating
}
```

这段伪代码保留了当前实现最重要的概率语义和失败分支。真正代码还包含 Worker 会话校验、V3 fallback、调试字段和评级持久化。
